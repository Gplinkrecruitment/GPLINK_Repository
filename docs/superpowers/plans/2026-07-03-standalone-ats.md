# Standalone ATS Implementation Plan (Zoho-optional GP Link ATS)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development — one subagent per task, sequential (all tasks touch server.js and/or ceo-dashboard.html). Steps use checkbox syntax.

**Goal:** GP Link becomes its own complete ATS — jobs, candidates, pipeline, interviews, offers, placements all work fully in-app with Zoho Recruit disconnected — hosted on the CEO dashboard, with a new "consultant" role for future recruiters (full ATS + pipeline control, nothing else).

**Architecture:** Zoho code stays but becomes optional (already degrades: tests run Zoho-unconfigured). The kanban `ats_stage` remains the pipeline source of truth. New in-app offer records + placement completion write the SAME shapes the Zoho path wrote (`gp_applications.status`, `gp_career_state.applications[].placement`), so every existing consumer (career.html secured view, AHPRA prerequisites, practice-contact lookups, admin panes) works unchanged. New storage uses tolerant table-or-runtime_kv fallback so everything functions BEFORE the owner applies DDL.
